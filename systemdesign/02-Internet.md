Before the Internet, things were simple.

You wrote a piece of code, ran it on your own machine, and used it.
That was a standalone application.

If someone else needed it, you just zipped the software or shipped it via CD / floppy disk.
They installed it on their system, and it used their own RAM, CPU, and hard disk.

Every user had their own copy of the software.
No sharing. No scale. No complexity.

Then the Internet happened.

At first, it was just a faster way to transfer software.
But soon people realized something powerful :

What if I keep the software on my machine, and others just send requests to it?

Using the HTTP protocol, users from anywhere in the world could send a request,
and the program would process it and send back a response. Hence the program would use only one computer’s resource. We call it a server. Since it serves the request. 

That’s how web applications (websites) were born.

Now one application was serving thousands or even millions of users all around the world and the single computer called server is used and all its resource is being shared like the same CPU, memory, disk, and network.

And that single change is exactly why System Design came into existence.
